# llm-router

A gateway that decides, per request, whether a **small, cheap model** or a **large, stronger model** should answer, and a
benchmark that measures what that routing costs and saves in quality, money and latency.

> **Status: v0 plus one pre-registered follow-up, built in one overnight sprint.** The gateway, routers, cascade experiment and
> evaluation harness are built and tested. The benchmark is small (hundreds of questions) and there is no load test or Redis cache.
> Numbers are in `results/report.md`, generated by `python -m llm_router evaluate`. They are not copied here by hand.

## What v0 found (see `results/report.md` for numbers and intervals)

- The large model is more accurate than the small one on this benchmark, and costs several times more per request.
- An oracle that always knew when the small model would fail could keep near-large accuracy at a fraction of the large
  model's cost, so routing has real headroom here.
- **Neither router captured it.** The rules router did no better than always-small. The learned router, at its
  pre-fixed threshold, was not distinguishable from a random mix sending the same share of traffic to the large model.
  An exploratory diagnostic (added after seeing that result, and labeled as such in the report) found its ROC-AUC
  indistinguishable from 0.5, overall and within each source. With few small-model failures to learn from, prompt
  embeddings carried no usable signal about when the small model will fail.
- So v0 is a negative result for these two routers, on top of a working gateway and a measurement harness whose
  baselines (oracle, random mix) are what make that negative result interpretable.

### Follow-up: cascade on small-model self-consistency (`results/cascade_report.md`)

The rule was **pre-registered in git before any sample was collected** (`docs/superpowers/specs/2026-11-08-cascade-preregistration.md`):
sample the small model 3 times at temperature 0.7 and escalate to the large model unless all answers agree. Nothing is trained.

- **The signal is real.** On the pre-registered primary test, the cascade beat a random mix that escalates the same share of
  questions. The small model was far more accurate when its samples agreed than when they disagreed.
- **It did not turn into a cost win.** The cascade pays for three small calls on every request. In a post-hoc comparison (added
  after seeing the primary result and labeled that way in the report) it was not distinguishable from a random mix spending the
  same money, its accuracy stayed below always-large, and its tail latency was worse.
- Cheaper failure signals (two samples, token log-probabilities, output length) are the obvious next step. They were not run, to
  keep the pre-registered result as the headline.

## What it does

```
client ──► FastAPI gateway ──► router(policy) ──► model pool ──► small tier | large tier
              │  SSE streaming      │                 │
              │  LRU cache          └ always_small / always_large / rules   (live gateway)
              │  /metrics           fallback to the other tier if a model fails or times out
              └  per request: TTFT, total latency, tokens (incl. thinking), cost, chosen tier
```

- **Pool** (`llm_router/pool.py`): streams from Gemini models, counts billed tokens (thinking tokens are billed as output),
  prices them from `config.yaml`, and falls back to the other tier only if the chosen one fails *before* sending any text.
- **Gateway** (`llm_router/gateway.py`): `POST /v1/complete`, `POST /v1/stream` (SSE), `GET /metrics`, `GET /healthz`.
  Fallback answers are never cached under the tier that failed.
- **Policies** (`llm_router/policies.py`):
  - `always_small`, `always_large`: the baselines.
  - `rules`: a fixed heuristic (LaTeX commands, math symbols, technical vocabulary, or long prompts go to the large model).
  - `learned` (offline evaluation only, **not wired into the live gateway**; its trained model is not saved or served):
    logistic regression on `bge-small` prompt embeddings that predicts whether the small model will be correct;
    it routes to the small model when that probability is at least a threshold.

## How the evaluation works

1. **Questions**: GSM8K (numeric) and a slice of hard MMLU subjects (multiple choice). Quality is exact match on the final
   number or letter. There is **no LLM judge**, so there is nothing to calibrate.
2. **Collect once**: every question goes through both tiers a single time; correctness, latency, tokens and cost are recorded.
3. **Replay**: each policy is scored offline against those recorded outcomes on a held-out half. The other half trains the
   learned router. The split is seeded and stratified by source.
4. **Statistics**: 95% paired bootstrap intervals over test questions. Every policy is scored on the same resampled
   questions, so differences between policies are paired.
5. **Baselines that keep the router honest**: an oracle (upper bound on what routing could achieve) and a random mix that
   sends the same fraction to the large model. The router only has skill if it beats the random mix.

**Decisions fixed before any held-out result was computed:** the rules router's cues and length limit, and the learned
router's headline threshold (0.9). Other thresholds are shown for context only.

## Honest notes

- A 28-question pilot on a different seed was run first. It exposed a bug: the small model ends answers with
  `\boxed{B}`, which the first answer extractor missed, making the small model look far worse than it is.
  The extractor was widened to accept `Answer: X`, `\boxed{X}`, "final answer is X" and "correct option is X",
  applied identically to both models, with tests. Stored responses are re-graded with `python -m llm_router rescore`.
  The main run happened after that fix.
- Latencies come from the collection run under 8-way concurrency. They are not a load test.
- Prices are list prices copied into `config.yaml` on the date noted there; verify them before relying on cost figures.

## Run it

```bash
uv sync
cp .env.example .env              # add GEMINI_API_KEY (never commit it)
uv run python -m llm_router list-models
# edit config.yaml: model names and prices
uv run python -m llm_router probe --model <name> --n 8
uv run python -m llm_router collect       # resumable; writes results/collect.jsonl
uv run python -m llm_router evaluate      # writes results/report.md and results/summary.json
uv run python -m llm_router cascade-collect   # 3 small samples per question (resumable)
uv run python -m llm_router cascade-evaluate  # writes results/cascade_report.md
uv run python -m llm_router serve         # gateway on :8000
uv run pytest
```
